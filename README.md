# text2card · 文案卡片美化

把任意文本 / 代码 / Markdown / 诗词，一键变成可分享的精美图片。

纯前端，零后端，无需登录。审美是第一优先级。

**在线体验** → <https://text2card-q3j.pages.dev/>

## 特性

- **4 套独立设计语言的卡片**，按内容自动建议、手动可换：
  - 代码（Carbon 风暗色 IDE，6 个 VS Code 主题）
  - 金句（大字海报，4 套柔和渐变 + 装饰引号）
  - 长文 Markdown（杂志风，3 套配色，标题/列表/引用/代码块全自定义渲染）
  - 中文古典诗词（竖排宣纸，自动从《》和 —— 提取标题作者；
    印章与标点符号各有开关，均默认不显示）
- **内容启发式分类器**：粘贴即识别，chips 上会标 `自动 · 长文` 这样的判定
- **保存与「最近」**：一键把当前诗词、背景、AI 背景图和全部预览设置存成快照，
  最多留最近 20 条，点一下即可载回主界面
- **可换字体**：中文 24 档 + 西文 10 档共 34 档，分组可折叠，
  作用到正文与标题；**字号**可在 70%–150% 之间无级调节
- **AI 背景图（诗词卡可选）**：把诗词拆成 主体 / 环境 / 风格 / 光影 / 构图 五个独立字段，
  逐字段可改，再拼成提示词交给大模型出图，作为卡片底图（见下文）
- **3 种导出尺寸**：自适应（宽 1080）/ 3:4 竖图（1080×1440）/ 16:9 横图（1920×1080）
- **一键导出 PNG**，`pixelRatio: 3`，分享到手机不糊
- **纯前端 · 隐私**：渲染与导出全部在你的浏览器里完成，卡片渲染不依赖任何服务端。
  唯一会联网的功能是 **AI 背景图**，且只在你主动点「自动拆解 / 生成背景」时才把
  诗词正文或提示词发给模型；不用这个功能就完全离线

## 运行

要求 Node.js ≥ 18（Vite 5 的最低要求），macOS / Windows / Linux 均可。

```bash
npm install
npm run dev
```

浏览器打开 <http://localhost:5173/>。导出 PNG 建议使用 Chrome / Edge 等
Chromium 系浏览器——html-to-image 的 DOM→SVG→canvas 渲染路径在 Safari
上有已知 bug（字体丢失、图像空白）。

构建生产版本：

```bash
npm run build
npm run preview
```

## AI 背景图（诗词卡）

把一首诗变成「五字段 → 提示词 → 背景图」，作为诗词卡的底图。

### 配置密钥

图像与文本都走**火山方舟**，一套 `ARK_API_KEY` 同时用于拆解与出图。

本地开发：

```bash
cp .env.example .env      # 然后填入 ARK_API_KEY
```

`.env` 已在 `.gitignore` 里。密钥只被 Node 进程读取，**不会进前端 bundle**
（构建产物里检索 `ARK_API_KEY` / `ark.cn-beijing` 均为 0 命中）。

线上（Cloudflare Pages）：在项目的
**Settings → Environment variables** 里加一个 `ARK_API_KEY` 即可。生产环境由
`functions/api/*.ts`（Pages Functions）承接同样的接口。

### 使用流程

1. 左侧粘贴诗词，顶栏切到 **诗词**（或让它自动识别）
2. 右侧「AI 背景」→ 点 **自动拆解**：文本模型输出五个字段并填入输入框
3. 按需手改任一字段——提示词始终以面板内容为准，自动拆解只是给个起点
4. 展开 **提示词预览** 可以看/复制最终提示词
5. 点 **生成背景**：出图后自动铺为卡片底图，并可调「蒙层」浓淡
6. 正常导出/复制 PNG，背景图会一起导出

### 五个字段

| 字段 | 职责 | 示例 |
|---|---|---|
| 主体 | 画面唯一核心实体 | 一叶孤舟 |
| 环境 | 时空、天气与陪衬景物 | 寒江暮色，远山薄雾 |
| 风格 | 绘画媒介与流派 | 水墨写意，淡彩渲染 |
| 光影 | 光源方向与色调 | 月华清冷，侧逆光 |
| 构图 | 取景视角与留白 | 竖幅三分法，左侧大片留白 |

拆解与拼装共用 `shared/scene.ts`：服务端按同一份字段元数据生成结构化输出要求，
前端按同一份元数据拼提示词，两边不会漂移。

### 两个设计取舍

- **蒙层复用主题自己的渐变**，而不是加一层黑色遮罩。照片退成一层「淡底画」，
  文字颜色照旧由主题的 `text` 决定——对比度不依赖对图片做明暗分析，换主题时
  整张卡的观感也跟着变。蒙层**默认 50%**，滑杆可在 0–90% 之间调。
- **图片以 data URL 内联**，不用远程 URL。远程图片会污染导出用的 canvas
  （`toBlob` 直接抛安全异常），而且会被方舟 CDN 的 CORS 挡掉；服务端回源取字节
  后转 data URL，浏览器侧永远是同源数据。

### 可选环境变量

全部可留空，用代码内默认值。报「模型不存在 / 无权限」时优先改前两个：

| 变量 | 默认 | 说明 |
|---|---|---|
| `ARK_TEXT_MODEL` | `doubao-seed-2-1-pro-260915` | 拆解用文本模型 |
| `ARK_IMAGE_MODEL` | `doubao-seedream-4-0-250828` | 出图模型 |
| `ARK_IMAGE_SIZE` | `2K` | Seedream 4.x/5.x 用 `1K`/`2K`/`4K`；实测 2K + 竖版提示词出 1728×2304 |
| `ARK_IMAGE_RESPONSE_FORMAT` | `b64_json` | 换成 `url` 则服务端回源下载后再转内联 |
| `ARK_BASE_URL` | 方舟北京区 | 走自建网关时改 |

> 默认模型 ID 是实测返回 200 后才写进代码的，但**模型可用性随账号与开通状态而变**：
> 方舟要求先在控制台开通模型，未开通时同一 ID 会返回
> `InvalidEndpointOrModel.NotFound` 或 `ModelNotOpen`。这两类报错都带方舟原始
> Request ID 并直接显示在界面上，照着换成你账号可用的 ID 即可。
> 查询方式：`GET {ARK_BASE_URL}/models`（注意 `status: Shutdown` 的是已下线模型，
> 列出来也调不通）。
>
> 出图命中 400 时，服务端会自动摘掉 `response_format` /
> `sequential_image_generation` / `stream` 重试一次——但**不会**摘掉
> `watermark: false`，宁可失败也不接受一张烧了水印的卡片背景。

### 已知限制

- 生成的背景图**不写入 localStorage**（动辄数 MB，会撑爆配额），刷新后需重新生成；
  五个字段本身会持久化
- 出图尺寸默认 `2K`，而导出是 1080 宽 × `pixelRatio: 3` = 3240px，
  背景会被放大，追求极致锐度可设 `ARK_IMAGE_SIZE=4K`
- 背景图目前只作用于诗词卡

## 保存与「最近」

顶栏 **保存** 把当前全部界面状态存成一条快照：诗词正文、风格、尺寸、
主题、标题/作者/眉头、竖排/横排、留白、**字体**、五个画面字段、
以及**AI 背景图与蒙层浓度**。顶栏 **最近** 打开列表，最多保留 20 条，
点任意一条即可整套载回主界面，也可单条删除或全部清空。

### 为什么快照走 IndexedDB 而不是 localStorage

一张 AI 背景图的 data URL 就有 1MB 上下，而 localStorage 配额通常只有 5MB，
存两三次就会把整个站点的自动保存写崩——连草稿都保不住。所以两者分工明确：

| 通道 | 存什么 | 上限 |
|---|---|---|
| `localStorage` | 当前工作草稿（不含背景图，防撑爆） | 1 份，自动保存 |
| `IndexedDB` | 显式保存的快照（**含**背景图） | 20 份 |

配额写满时不会直接报错：会淘汰最旧的一条再重试（最多 3 次），
避免「存到某个体积后就再也存不进新内容」这种没有自救手段的死局。

### 一个容易踩的坑

载入快照时必须提前把「上一次的生效风格」对齐到恢复后的风格。否则
`setStyleChoice` 引起的风格变化会让「风格变了就重置主题索引」那个 effect
在本次渲染后触发，把刚恢复的 `themeIndex` 清成 0——表现就是
「载入后主题总是回到第一个」。见 `App.tsx` 的 `handleRestore`。

## 字号

右侧「字号」是一根滑杆，范围 **70%–150%**，作用范围与字体一致（**正文与标题**），
署名、眉头、文件名栏、印章不参与缩放。旁边非 100% 时会出现「复位」。

倍率是在各卡片**自己算好的字号**上再乘的——卡片本来就会按文字长度自动挑字号
（短句更大、长文更小），滑杆是在这个基础上微调，不是覆盖它。

上限刻意只到 150%：卡片高度是固定的（3:4 / 16:9），字号放大必然溢出被裁。
与其让用户撞上截断提示，不如把范围收在「一般还装得下」的区间；真需要更大，
应该配合「尺寸 → 自适应」一起用（自适应会把卡片高度撑开）。

### 为什么放大字号时「背景图也变了大小」

**背景图其实没变，是整张预览被缩小了。** 自适应模式下卡片高度随内容增长，
而预览为了把整张卡塞进视口，会按 `min(可用宽/卡宽, 可用高/卡高)` 等比缩放——
所以背景图、文字、印章是**一起**变小的。

实测（一首四句五言，自适应尺寸）：

| 字号 | 卡片实际尺寸 | 预览缩放 | 背景层宽高比 |
|---|---|---|---|
| 100% | 1080 × 979 | 70% | 1.103 |
| 150% | 1080 × 1086 | **63%** | 0.994 |

背景层（`inset:0`）跟着卡片长高，但 `background-size: cover` 的缩放
由**宽度**主导（1080/图宽 > 979/图高），所以图在卡片内部的缩放级别
**一模一样**——变的只是预览的显示倍率。导出走 `node.offsetWidth/Height`，
是卡片的真实尺寸，不受预览缩放影响。

预览右下角有一行 `1080 × 1086 · 预览 63%` 的读数，就是给这件事做说明的。

**想要放大字号时画面完全不动的做法：把尺寸切到 3:4 或 16:9。**
固定尺寸下卡片长宽不变，预览缩放也不变（实测 100% 与 150% 都是
`1080 × 1440 · 预览 47%`）。

## 字体

右侧面板「字体」分**中文 / 西文**两组、共 34 档（中文 24 + 西文 10），
分组可折叠（初始只展开当前选中项所在那一组；折叠时组标题右侧会显示选中的
是哪一档）。全部 self-host，不产生任何外部请求（否则导出的 PNG 会因字体
未加载而回退系统字体，屏幕预览与导出结果就不一致了）：

| 组 | 档位 |
|---|---|
| **中文** | 默认 · 宋体（Noto Serif SC） · 文楷（LXGW WenKai） · 黑体（Noto Sans SC） · 晰黑（LXGW Neo XiHei） · 楷书（Ma Shan Zheng） · 楷体（FZKai-Z03） · 仿宋（FZFangSong-Z02S） · 大楷（Alimama DongFangDaKai） · 小薇（ZCOOL XiaoWei） · 珠圆（MaokenZhuyuanTi） · 快乐（ZCOOL KuaiLe） · 庆科（ZCOOL QingKe HuangYou） · 得意（Smiley Sans） · 无锋（MDMD-WuFengTi） · 龙珠（LogoSC LongZhuTi） · 龙藏（Long Cang） · 悠哉（Yozai） · 小赖（Xiaolai SC） · 行书（Zhi Mang Xing） · 弘雷（hongleixingshu） · 拙书（HongLeiZhuoShu） · 草书（Liu Jian Mao Cao） · 甲骨（FZJiaGuWen） |
| **西文** | 等宽（JetBrains Mono） · Plex（IBM Plex Mono） · Fraunces · Garamond（EB Garamond） · Cormorant（Cormorant Garamond） · Lora · Playfair（Playfair Display） · Manrope · Caveat · Vibes（Great Vibes） |

作用范围是**正文与标题**；署名、眉头标签、文件名栏这类装饰性文字
保持原设计，避免整张卡失去层次。

> 日文那两组（Klee One / Yuji Syuku）已经移除——它们虽是汉字，但字形是
> 日式的（「直」「骨」「今」写法与简体不同），简体专用字还要回落，对这个
> 项目没什么用。

### 两个「选了没反应」的坑

这两个都不是 bug，但不说明白就会被当成 bug：

- **宋体 = 诗词正文的默认字体**，在诗词卡上选它当然看不出变化
  （在金句 / 长文 / 代码卡上是有变化的，那些卡的默认字体不是宋体）。
- **4 个西文选项没有中文字形**，正文是中文时会回落到后面的中文字体。
  面板上选到这些会显示提示。

判断「换字体有没有生效」不能看排版尺寸：中日韩字形在所有字体里都是
**全角等宽**，换字体只改字形、不改宽度。要靠字形本身比对。

### 按需加载

可选字体的 CSS **不静态引入**。它们的 `@font-face` 规则合计 600 多条
（每个中文字体按 unicode-range 切 90–100 片），全量引入会把 CSS 从
266KB 顶到 1086KB（gzip 107→490KB），而绝大多数访客只会用默认那几套。

所以 `lib/fonts.ts` 里的 `ensureFontLoaded()` 在**选中时**才动态 import
对应 CSS，Vite 会为每个包单独切一个 chunk：默认 CSS 保持 269KB，
8 个可选字体各是一个 105–152KB 的独立文件，不选就不下载。字体文件本身
同样只下载用到的分片。

唯一代价是首次选中时有一瞬间的回退字形（`font-display: swap`）。

### 加新字体时要当心

**不是所有中文字体包都能直接用。** 加字体时踩过两个坑：

**坑一：包可能完全没分片。** `@fontsource/lxgw-wenkai` 没有按 unicode-range
切片，单个 woff2 就有 **6.9–8.4MB**（而且文件名叫 `latin` 却装了整套中日韩
字形，标签是错的），还缺 400 字重。改用官方网页版 `lxgw-wenkai-webfont`：
582 个分片、最大单片 60KB。

**坑二（更隐蔽）：「最大单片小」不等于「下载少」。** 实测一首 20 字诗真正
会拉取的分片量：

| 字体 | 分片数 | 单片最大 | **一首诗实际要下** |
|---|---|---|---|
| 站酷小薇 / 龙藏 | 12 | 0.08 MB | **0.77 MB** |
| 霞鹜文楷 | 97 | 0.06 MB | **4.42 MB** |
| Klee One | 17 | 0.05 MB | 0.37 MB |
| Yuji Syuku | 17 | 0.06 MB | 0.53 MB |

文楷的单片最小，但因为切得太细，一首诗要拉 97 片、比站酷系列重 6 倍。
**判断字体贵不贵要看「命中多少片 × 每片多大」。**

**坑三：有些字体看起来有用，其实字形完全相同。** 曾加过一档「繁宋」
（`@fontsource/noto-serif-tc`），实测后删掉了——思源宋体的 SC 与 TC 是同一套
字形设计，逐像素比对在简体诗、繁体诗、以及「直骨今画」这类区域差异字上
**全部一模一样**。加进去只是个「选了没反应」的摆设。

所以加字体前至少确认三件事：**有没有 `unicode-range` 分片**、
**实测一首诗要下多少**、**换上去是否真的改变了字形**。

### 授权情况（商用前请看）

新增的中文字体来自两类来源，**授权清晰度不一样**：

| 授权 | 字体 |
|---|---|
| **SIL OFL 1.1（开源，可商用）** | 晰黑（LXGW Neo XiHei）、悠哉（Yozai）、小赖（Xiaolai SC）、龙珠（LogoSC LongZhuTi）、得意黑（Smiley Sans，上游为 OFL） |
| **作者声明免费商用，但包内 `license` 字段为 unknown** | 大楷（阿里妈妈东方大楷）、楷体（方正楷体）、仿宋（方正仿宋）、弘雷、拙书、珠圆、无锋 |
| **授权最不明确** | 甲骨（方正甲骨文）——方正字体商用需按其授权条款确认 |

`cn-fontsource-*` 这一系列包的元数据里 `license` 大多写 `unknown`，只在
`font.type` 标了 `free`，并链到猫啃网的介绍页。**要商用/公开发布前，请按
版权方页面逐项确认**；纯自用则无碍。要我把上表后两类直接删掉，说一声即可。

```bash
# 1) 分片数与 unicode-range 条数应当相等
grep -c 'unicode-range' node_modules/<包名>/400.css
# 2) 最大的分片
ls -S node_modules/<包名>/files | head -1
# 3) 字形是否真的不同：用 canvas 逐像素签名比对（中文字形全角等宽，
#    量宽度是量不出区别的——六种字体宽度会完全一样）
```

这个区块刻意排在右栏**最末**。右栏是 `overflow-y-auto` 的窄栏，任何插在
中间的新区块都会把它下面所有内容往下推：它一度被放在「主题」后面，
结果把「AI 背景」挤出首屏，看起来就像那个功能消失了。
新增区块请往末尾追加。

代码卡略微特殊：`shiki` 会给自己生成的元素加内联样式，而
`styles/index.css` 里那条 `.shiki { font-family: ... !important }` 会压掉
组件上的 `fontFamily`，所以代码字体是通过 CSS 变量 `--code-font` 注入的
（未设置时回退 JetBrains Mono）。

## 使用

1. 左侧粘贴文本（或点击左侧编辑栏的 `示例：金句 / 代码 / 长文 / 诗词` 载入示例）
2. 左侧底部填 **标题 / 作者**（各风格叫法不同：代码是「文件名」、金句是「署名」）。
   诗词 / 长文 / 金句还可以点 **解析题目 / 作者**，从原文里自动拆出来
3. 中间实时预览（手机端首次默认 3:4 竖图）
4. 顶栏 chips 切换**风格**（卡片样式）；右侧「调整」面板选尺寸 / 留白 / 主题 / 字体
5. 右上角 **复制图片** 或 **导出 PNG**（⌘/Ctrl+S）；**保存** 把当前状态存进「最近」

### 各卡片识别规则

| 内容形态 | 自动归类 |
|---|---|
| 含 \`\`\` 代码围栏，或前几行多为 `function/class/import/<...>` 等 | **代码** |
| 短句 ≥ 4 句且**句长完全一致**、长度属于 4/5/7 字（四言、五言、七言），或含《标题》 | **诗词** |
| 含 Markdown 语法（`#`、`-`、`>`、表格 等）或 > 300 字 | **长文** |
| 短句、有引号包裹、≤ 140 字 | **金句** |

判错也没关系——chips 一点就换。

**诗词的判定偏严，这是刻意的。** 只要求「每句 4-9 字」会把现代文案也判成诗词
（「愿你慢慢长大，愿你有好运气…」句长 6/6/4/11），所以额外要求句长整齐且
属于古典常见句长。代价是几类内容认不出来，需要手动点「诗词」：

- **宋词、古体诗**：句长本就不整齐（如「大江东去，浪淘尽，千古风流人物」）
- **只有两句的短诗**：与两句现代短句无法区分（如「人生若只如初见，何事秋风悲画扇？」）
- **六言诗**：少见，为挡住「全是 6 字的现代文案」而未纳入

> ⚠️ 这一点很重要：**AI 背景面板只在生效风格是「诗词」时渲染**。
> 风格选「自动」时由上面的分类器决定，判成别的风格，那个面板就不会出现
> ——看起来就像功能消失了。手动点一下顶栏的「诗词」chip 即可。

代码围栏的语言标记支持常见简写（\`\`\`js、\`\`\`py、\`\`\`sh 等），写了无效语言时会自动回退到代码内容检测。

### 各卡片支持的元数据

这些字段都在**左侧编辑栏底部**，紧贴正文——它们本来就是从正文里拆出来的，
放在一起才好对照。（只有长文的「眉头标签」留在右侧面板，它属于版式而非内容。）

| 卡片 | 字段 |
|---|---|
| 代码 | 文件名（不填会按语言自动猜 `snippet.ts` 之类） |
| 金句 | 署名 |
| 长文 | 眉头标签 / 标题 / 署名 |
| 诗词 | 标题 / 作者 / 竖排或横排 / 显示印章 / 显示标点符号 |

### 诗词卡的两个显示开关

右侧「显示」分组里有两个勾选框，**都默认关**：

- **显示印章** — 右下角那枚方章（刻「閒」字，取主题的 `seal` 色）。默认不显示。
- **显示标点符号** — 关掉时按古典竖排惯例隐去句读，只去掉 `，。、；：！？…—`
  这类句读标点，**不动书名号《》与引号**（它们在诗句里是内容的一部分，
  去掉会改变语义）。

标点是在**渲染时**去掉的，编辑区里的原文始终是用户敲进去的样子——
否则一勾「显示标点」就再也找不回来了。导出的 PNG 与屏幕所见一致。

默认关掉让卡片更接近传统竖排诗词的观感；需要保留标点时勾上即可。

### 从原文解析题目 / 作者

诗词 / 长文 / 金句的编辑栏里有 **解析题目 / 作者** 按钮，点一下就从原文里
拆出题头并把它们从正文中移出。识别的是这些写法：

| 写法 | 例子 |
|---|---|
| 书名号 | `《江雪》` |
| 显式标注 | `题目：江雪`、`标题：静夜思` |
| Markdown 标题 | `# 江雪` |
| 一行同时给出 | `江雪 · 柳宗元` |
| 首行短、正文更长 | `江雪` 单独一行 + 后面的诗句 |
| 破折号落款 | `—— 柳宗元` |
| 显式署名 | `作者：柳宗元` |
| 题目下一行 | `江雪` / `柳宗元` / 诗句… |
| 括号署名 | `（唐）王维` |

用本地规则而不是大模型：粘贴后要立刻出结果，规则匹配即时、免费、可离线；
语义层面的理解由方舟拆解负责，两者分工不重叠。

判定原则是**宁可少认，不可错认**——把诗的第一句当成题目，比没解析出题目更糟。
两条关键防线：

- **题目**：拿掉首行后，其余行的平均长度必须**严格大于**首行。这样「每行都是
  5 字」的四句五言不会被误判成「首行是题目」。
- **作者**：题目下面那行也要求后续诗句更长。否则
  `静夜思 / 床前明月光 / 疑是地上霜 / …` 会把「床前明月光」当成作者。

另外破折号规则**不接受单个半角连字符**，因为 `- 第一点` 是 Markdown 列表项，
放宽会把每个列表的第一条当成署名。

解析会改写正文，所以结果条上带一个 **撤销**，一键还原到点击前的状态。

- [火山方舟](https://www.volcengine.com/product/ark) — 诗词拆解（文本模型）与背景图生成（Seedream）

## 自定义主题

每个 `themes/*.ts` 文件是一个数组，复制一项改色值即可：

```ts
// themes/quoteThemes.ts
{
  name: '夜空',
  background: 'radial-gradient(... ) , linear-gradient(...)',
  text: '#ffffff',
  accent: '#ffd166',
  rule: 'rgba(255,255,255,0.25)',
  quoteMark: 'rgba(255,209,102,0.2)',
  noise: 0.08,
}
```

保存后 dev server 热更新，右侧主题面板会自动出现新项。

## 字体

通过 [@fontsource](https://fontsource.org/) 本地打包（self-host），无任何外部请求，
国内网络可用、可离线运行：

**首屏静态引入（各卡片的默认排版，5 套）**

- **Fraunces Variable** — 英文衬线（金句 / 长文标题，含光学尺寸轴）
- **Inter** — 英文 sans（UI / 署名）
- **JetBrains Mono** — 等宽（代码）
- **Noto Serif SC Variable** — 思源宋体（中文金句 / 诗词 / 长文正文）
- **Ma Shan Zheng** — 楷书（诗词标题）

**可选字体（18 套，选中时才按需加载）**

其余档位见上文「字体」一节，各自是独立的 CSS chunk，不选就不下载。
默认字体必须静态引入，否则首屏会出现字形回退；可选的则不能静态引入，
否则 CSS 会从 269KB 涨到 MB 级。

CJK 字体按 unicode-range 分成上百个小片，浏览器只下载页面实际用到的片。
导出时会把已加载的字体分片内联进图片，**导出结果与屏幕渲染完全一致**。

## 已知限制

- **导出耗时约 1.5–2 秒**：导出管线会等待 SVG 内嵌字体就绪并校验渲染稳定，
  这是字体保真的代价。
- **自适应尺寸** 默认 min-height 900px（避免极扁卡片），短内容底部会留白；
  右侧「留白」可切「紧凑」让卡片贴合内容，下限按卡片类型区分（一般 480px、
  代码 680px）；竖排诗词需要高度排列、不参与紧凑（其「留白」开关自动隐藏）。
